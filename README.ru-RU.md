## 🎮 Обзор

Плагин масштабирования тактического обзора для Command & Conquer: Yuri's Revenge. Увеличивает обзор на уровне рендера, удерживает точку под курсором, управляя игровой камерой, и обратно преобразует координаты ровно там, где игра переводит экранные позиции в игровое пространство — клики и выделения попадают именно туда, куда вы смотрите.

Построен на **Windows API** с использованием **Syringe** (фреймворк инъекций, тот же, что у Ares, Phobos и других расширений YR) для загрузки и управления жизненным циклом. Только code-хуки — исполняемый файл игры и её ресурсы на диске никогда не изменяются.

## ✨ Возможности

- 🔍 **Ctrl + колесо мыши** — масштабирование тактического обзора: шаг 1.15, диапазон 1.0×–4.0×, плавная интерполяция, не привязанная к FPS
- 🎯 Точка под курсором остаётся на месте: игровая камера смещается на каждом шаге зума
- ↩️ **Двойное нажатие Ctrl** (в течение 400 мс) сбрасывает зум до 1.0×; накопленное смещение камеры откатывается автоматически при возврате к 1.0×
- 🧭 **Стрелки** — панорамирование обзора при активном зуме
- 🖼 Увеличение на уровне рендера: прямоугольник обзора сохраняется и растягивается (nearest neighbour) поверх уже отрисованного кадра
- 🧰 Масштабируется только тактический обзор — панель, HUD и физический курсор не перенаправляются
- 🧮 Координаты преобразуются только там, где это делает игра (клики, рамка выделения, правый перетаскивание)
- 📦 Без зависимости от GScript: фактор зума живёт целиком в ViewCtrl — а если мод привозит свой собственный масштабатор, ViewCtrl уступает ему вместо конкуренции (см. Статус)
- ⚡ Минимальные накладные расходы

## ✅ Статус

- 🧪 **Юнит-тесты:** 69 тест-кейсов / 653 проверки — `tests\bin\ViewCtrlTests.exe`
- 📊 **Покрытие строк:** 99.7% `src/` (измерено OpenCppCoverage по doctest-набору; остаток — несколько защитных веток сбоя ОС)
- ⚠️ **Автоопределение конкурирующих масштабаторов** (подробнее: [docs/conflict-detection.md](docs/conflict-detection.md)): если мод сам масштабирует обзор — `GScript.ext` (например, Tiberium Crisis), Telescope v1.4, Kaleidoscope, MOExperience или Ra2.Vampire.Zoom — `GameInt` это обнаруживает и оставляет ViewCtrl неактивным. Обнаружение многослойное: **L1** имя файла модуля, **L2** отпечаток таблицы хуков `.syhks00`, **L3** сканирование байтов на чужие патчи `E9`, **L4** реактивный мониторинг размера обзора, **L5** проверка характерных экспортов — переименованный или пропатченный на лету конкурент тоже будет пойман
- 🔬 **Статический аудит:** каждый адрес хука сверен с YR Hook Encyclopedia — безопасен для Syringe-стаба (нет относительных переходов внутри «украденных» окон, адреса возобновления на границах инструкций), конфликтов в реестре хуков нет; bootstrap-хук `0x52CAE9` разделяется с Ares (`_YR_PostGameInit`) и корректно с ним композируется
- 🖥 **Порядок рендера проверен дизасемблированием:** увеличение выполняется после того, как игра рисует в `DSurface::Composite`, до блика курсора и до `Frame::Present` — на экран попадают увеличенные пиксели
- 🛡 **Хуки под SEH-защитой:** тело каждого хука обёрнуто в `__try/__except`, поэтому сбой при обращении к некорректной игровой памяти проглатывается и воспроизводятся исходные байты инструкций вместо падения игры; в тестовой сборке гарды отключены, чтобы тесты по-прежнему ловили реальные баги
- 🎮 **Проверено в игре** на Yuri's Revenge 1.001 (модифицированная установка, 1920×1080): диапазон и «якорь» зума, преобразования кликов и выделения, сброс и откат

- Рантайм: фреймворк инъекций Syringe для загрузки DLL

## 📥 Установка

1. Убедитесь, что игра запускается через Syringe (`Syringe.exe` или лаунчер мода на его основе)
2. Положите скомпилированную DLL в корень игры
3. Зарегистрируйте DLL в конфигурации загрузчика Syringe
4. Запустите игру — Release-сборки работают молча и по умолчанию ничего не пишут; чтобы получить диагностический лог без пересборки, установите переменную окружения `VIEWCTRL_LOG=1` перед запуском (лог уходит в вывод отладчика / DebugView). Debug-сборка всегда пишет `ViewCtrl.log` рядом с исполняемым файлом игры

## 🔨 Сборка

`YRpp` (заголовки Syringe) — git-submodule, поэтому клонируйте рекурсивно:

```bash
git clone --recurse-submodules https://github.com/YoVVassup/RA2YR-Zooming.git
```

Если клон уже есть, инициализируйте submodule один раз:

```bash
git submodule update --init
```

Затем соберите `Release|Win32` (toolset v143):

```bash
msbuild viewctrl.vcxproj /p:Configuration=Release /p:Platform=Win32
```

Тесты лежат в `tests\test.vcxproj` и собираются только как `Debug|Win32`:

```bash
msbuild tests\test.vcxproj /p:Configuration=Debug /p:Platform=Win32
tests\bin\ViewCtrlTests.exe
```

## 🎛 Управление

| Действие | Эффект |
|----------|--------|
| **Ctrl + колесо мыши вверх/вниз** | Приблизить / отдалить (×1.15 за шаг, ограничение 1.0×–4.0×) |
| **Двойное нажатие Ctrl** (в течение 400 мс) | Сбросить зум до 1.0× и откатить смещение камеры |
| **Стрелки** (при активном зуме) | Панорамировать обзор |

Без Ctrl колесо передаётся игре без изменений. Все параметры зума — константы времени компиляции (`src\Zoomer.hpp`). Чтобы изменить их, отредактируйте исходники и пересоберите.

## 🤝 Совместимость

- Только хуки, исполняемый файл не переписывается — можно совмещать с другими Syringe-DLL (Ares, Phobos, ...); Syringe цепляет несколько DLL на общих сайтах
- `0x52CAE9` делит свои 5 байт с Ares `_YR_PostGameInit`; ViewCtrl после себя выполняет исходные байты, поэтому оба обработчика композируются
- Ранние сборки могли делегировать фактор зума GScript; ViewCtrl больше не читает и не пишет GScript — если собственная функция зума GScript активна, одна из двух отключается автоматически (см. [docs/conflict-detection.md](docs/conflict-detection.md))
- Масштабаторы на уровне дисплея (форки cnc-ddraw, Vampire.Zoom) меняют размер окна, а не прямоугольник обзора — они совместимы по загрузке, но совокупное увеличение обычно нежелательно
- Если вы столкнулись с проблемой совместимости с конкретным модом, откройте Issue с деталями и `ViewCtrl.log` от Debug-сборки (Release-сборки полностью выключают файловое логирование; включить транзиентное логирование можно через `VIEWCTRL_LOG=1`)

## ⚙️ Техническая реализация

- **Фреймворк инъекций:** Syringe `DEFINE_HOOK` — 9 хуков, все адреса централизованы в `src\GameAddrs.hpp` с аннотациями источников (YRpp / ReSource / Encyclopedia)

| Адрес | Байт | Назначение |
|-------|------|------------|
| `0x52CAE9` | 5 | bootstrap после инициализации игры (`InitGame`) — общий с Ares, композируется |
| `0x4F44AF` | 5 | перед рендером: восстановление чистого бэкапа обзора, тик лерпа зума |
| `0x4F451B` | 5 | после рендера: увеличение отрисованного обзора |
| `0x6D864E` / `0x6D868A` | 6 | `ClampCoordMap` — чтения ширины/высоты обзора ограничиваются увеличенным исходным прямоугольником (с откатом к последнему корректному размеру) |
| `0x692325` | 6 | `DisplayClass::ProcessClickCoords` — преобразование тактического клика |
| `0x6D9F80` / `0x6D9FC0` | 6 | преобразование начала/конца рамки выделения |
| `0x693791` | 6 | `ScrollMapEdge` — преобразование скорости прокрутки правым перетаскиванием |

- **Путь рендера (проверен дизасемблированием):** `MainLoop` → `GScreenClass::Render` (`0x4F4480`) рисует кадр в `DSurface::Composite` → ViewCtrl увеличивает → `wwmouse->DrawCursorBuffered` блитит неизменённый курсор → виртуальный `RenderFrame` → `Frame::Present`
- **Ввод:** подменяет оконную процедуру игры (`SetWindowLongPtrW`); колесо масштабирует только при зажатом Ctrl и курсоре над тактическим обзором, всё остальное передаётся игре; сама позиция курсора не перенаправляется
- **Камера:** каждый шаг зума двигает игровую камеру (`TacticalMapClass::SetCameraPosition`, `0x6D6000`), чтобы точка фокуса оставалась под курсором; при 1.0× смещение откатывается
- **Прямоугольник обзора:** `DSurface::ViewBounds`, опрос не чаще 250 мс и принимается только пока ничего не увеличено; сам прямоугольник не включает панель
- **Преобразования координат:** точки, где игра переводит экранные позиции в игровое пространство, обратно масштабируются; `Zoomer::UnMagnify` — точная обратная функция к апскейлу, который рисует рендерер
- **Надёжность:** тело каждого хука обёрнуто в SEH (`src\Seh.h`), поэтому сбой проглатывается и воспроизводятся исходные байты; логирование в Release по умолчанию выключено и переключается во время выполнения через `VIEWCTRL_LOG=1`
